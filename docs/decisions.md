# Technical decisions

- **Identity instead of number:** QueryDisplayConfig links GDI sources to target device paths. A normalized, sorted set of these paths is hashed. Mirror paths form one logical desktop area. Identical geometries are merged. If a path changes, a fixed action stays unassigned; model and geometry data are informational only.
- **Missing native identity:** A random session-scoped ID prevents an accidental permanent fallback assignment. An action saved this way must be reassigned manually after the program restarts. Dynamic cycles keep working.
- **Spatial defaults:** Sorted by screen center X, then Y, then identity. Fixed cycles explicitly allow a selected subset; the remaining displays stay untouched.
- **Coordinates:** Normal WINDOWPLACEMENT rectangles are offset by `rcWork.left/top - rcMonitor.left/top` into screen coordinates; tool windows stay in screen coordinates. The respective source/target monitor determines the offset. Maximized windows are first moved to the target as a maximized frame without activation; then the transferred normal restore position is set. SetWindowPlacement alone is not reliable for windows that are already maximized.
- **Geometry:** Transfer the relative center and keep the physical size. Only oversized windows get a 12 px margin per side and axis. Proportional mode scales by work-area size. After a DPI change, the application geometry may settle with a delay. At most two corrections within the shared waiting budget compensate for this; Snap tiles use the frame actually measured on the target. Win32/application minimum sizes can limit the adjustment further; a remaining layout deviation is then reported.
- **Snap and normal windows:** `GetWindowPlacement.rcNormalPosition` may still contain the size from before snapping. Normal windows are therefore moved and restored using their current GetWindowRect. The DWM visible bounds detect common screen halves, quarters and thirds from the work-area edges (8 px detection tolerance). Detected tiles keep their relative edges regardless of the size mode; invisible frames may extend beyond the work area. Windows-internal Snap groups are neither created nor manipulated through private APIs. Normal Undo compares the current position/size; changes only to latent restore metadata do not block it.
- **Owners:** A captured root owner determines the monitor route of its dialog group. Windows are processed from bottom to top; Z order and owner order are not explicitly reset. Pure tooltips/NoActivate overlays stay excluded.
- **Virtual desktops:** Only the documented IVirtualDesktopManager. Errors or unclear membership skip the window, in addition to the DWM cloaked check. No private COM interface, no desktop switching.
- **Focus:** NOACTIVATE/NOZORDER/NOOWNERZORDER, no AttachThreadInput and no simulated keystrokes. If Windows changes the global focus anyway, exactly one regular SetForegroundWindow attempt is made. Windows may reject it.
- **Slow applications:** Asynchronous SetWindowPos/SetWindowPlacement calls avoid hanging on foreign threads. All requests are sent before the result check. Shared verification rounds observe every window instead of letting one window use up the whole budget first. The shared waiting budget stays at 800 ms; it does not grow with the number of refusing applications. Windows that match early stay under observation during the running rounds. A window that reacts later is not monitored permanently.
- **Window DPI:** `GetDpiForWindow` is checked on the target for per-monitor-aware windows. `GetWindowDpiAwarenessContext` and `GetAwarenessFromDpiAwarenessContext` distinguish them from system-aware or DPI-unaware windows, whose DPI value may stay the same despite the monitor change. Documentation: [window DPI](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-getdpiforwindow), [window context](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-getwindowdpiawarenesscontext).
- **Undo:** A successful action replaces the last Undo set. A swap without any actually changed window does not discard the existing Undo. After Undo, completed or manually changed entries are consumed; entries deferred because of missing displays or execution errors stay available for another attempt. After layout changes, old pixel coordinates are never guessed.
- **Window identity:** HWND plus PID, thread, process start time and class. Foreign windows get no additional properties. HWND recycling within the same process with an identical class remains a rare, documented residual uncertainty.
- **Hotkeys:** RegisterHotKey with MOD_NOREPEAT, no keyboard hooks. A dedicated Win32 HWND instead of a Qt widget HWND, delivery via WndProc and a queued Qt signal. Registration and message delivery are tested separately. A new hotkey is registered under a free ID first, then the old one is released. Registration conflicts keep the previous hotkey. Requested startup bindings stay in the configuration so that conflicts are visible and can be checked again at the next start; the action can still be run from the tray.
- **Localization:** Plain JSON catalogs keyed by message ID instead of Qt Linguist `.ts`/`.qm` files: no compile step, usable from the Qt-free core, and supported by common translation platforms. English is the fallback for every key. Log events stay English identifiers; the diagnostic report is English in every UI language.
- **Privacy:** Process paths are read briefly for the exclusion check. Window titles are never read or logged. The program has no online features. External license links are opened in the browser only after a deliberate click.
- **Release:** Python 3.12 x64 as the tested build base. Pinned lock file, console-less onedir build in its own version folder, no installer and no signature. Autostart is never enabled automatically in tests or builds.
